# 手机后台播放

当前实现面向安卓 Chrome / 系统浏览器，沿用原生 HTMLAudioElement 播放。

- 接入 Media Session：系统通知栏/锁屏可获得歌名、歌手、专辑与封面，并处理播放、暂停、停止和下一首。下一首沿用房间的投票切歌，禁止切歌时不发送投票；不提供改变全房间进度的系统拖动操作。离房清理媒体信息和处理器。
- 支持 Audio Session API 的浏览器会在播放前声明 playback 类型，不支持则直接使用原生音频，不依赖这一实验接口。
- 隐藏页面时继续播放，停止周期同步 seek 与卡顿看门狗重载。后台 timer/timeupdate 可能延迟，回到前台时直接读取原生音频进度，重新校正看门狗基准，避免把 JS 停顿误判成音频停顿。
- 后台换歌保持当前主音频元素，使用提前准备/验证的地址更新音源，避免在后台切换到另一个尚未获得播放许可的元素。前台保留备用播放器切换；浏览器缓存的实际复用量由浏览器决定。
- 系统媒体暂停、网页手动暂停，以及原生音频被外部暂停，均停止自动恢复；后续换歌和前台恢复不会擅自播放。原生中断后提供继续收听入口。
- 前台恢复或 pageshow 时探测 WebSocket：关闭的连接立即重连；看起来 OPEN 但 3 秒内无响应的连接重新建立。旧连接的迟到事件不能覆盖新会话，重连快照不重置同一播放周期的音频。

Media Session 提供系统媒体集成，**不授予应用级后台保活权限**。它不能阻止系统杀浏览器进程，也不能保证冻结 JS 后继续收到每次 WebSocket 切歌。省电限制、厂商浏览器和应用内 WebView 的行为可能不同；不使用静音循环、屏幕常亮或 Service Worker 心跳来假装获得后台权限。

验证包括真实 Chromium 音频播放，以及模拟系统媒体操作、页面可见性变化、后台定时器延迟、系统暂停、WebSocket 假活的集成测试。模拟页面隐藏不等于真实安卓锁屏/进程调度，真机效果仍需在正式部署后验证。

手机验收：在 Chrome 中打开房间并点击开始收听，然后分别按 Home、切应用、锁屏，检查当前曲目和自然切歌；再用通知栏暂停/继续、投票切歌。手动暂停后等待房间切歌，确认不会自动开始；回到前台确认连接和进度恢复。另测来电/其他音频打断与厂商省电设置。
